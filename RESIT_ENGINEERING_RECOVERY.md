## 12. Optimizer Truth Record

- **What it does:** builds an OR-Tools routing problem to reorder stops and calculate a route result for existing route assignments.
- **What it does not do:** train or invoke ML/LLM; infer bin state; optimize road-network distance; move stops between existing route vehicles; measure fuel, carbon, cost or real-world savings.
- **Distance:** Haversine great-circle distance, rounded to meters; straight-line, not road distance.
- **Demand:** estimated from capacity × fill × fixed 0.10 kg/litre; clamped and rounded with a minimum 1 kg, including zero-fill bins.
- **Time:** assumed average speed and fixed service minutes per stop, subject to a configured hard duration; not observed traffic/travel time.
- **Membership:** each stop is constrained to its current route; the solver changes order within route membership.
- **Solver:** heuristic search with a time limit, so global optimality is not guaranteed.
- **Baseline:** current “before” may use a generated long order and cannot support measured savings.
- **Allowed wording:** “OR-Tools constrained route stop ordering prototype, using straight-line distance and stated demand/time assumptions.”
- **Forbidden wording:** AI/ML route optimizer, predictive, road-aware, measured fuel/carbon/ROI savings, city-scale fleet optimization.

## 14. Persistence Recovery

The active application uses SQLAlchemy ORM with SQLite in current Compose configuration. Route ordering rewrites bin identities through existing collection-history slots and commits in a request transaction. There is no migration framework in the reviewed startup path, explicit stable sequence column/unique route-stop constraint, or optimistic concurrency guard. Compose/mount layout does not establish DB-file survival across container replacement. Future work must define the route-order invariant, rollback semantics, persistence location and recovery procedure; verify them using a disposable environment. No database was read or changed in this phase.

## 21. Defence Rationale

- **Why reduce scope?** The selected route-ordering flow is more bounded and traceable than the combined simulated scanner, IoT, fleet and mobile feature set.
- **Why no longer describe it as AI-heavy?** Source establishes an OR-Tools heuristic and no trained model or inference path.
- **Why exclude features from core?** Their implementation/evidence does not support operational claims; exclusion makes assessment criteria testable without erasing their source history.
- **Why retain OR-Tools?** It provides a concrete constrained optimization component that can be explained, tested on fixtures and compared under explicit assumptions.
- **Why separate simulation from implementation?** Generated values and timer-based behavior cannot establish physical sensors, detection or measured outcomes.
- **Why is evidence different from the earlier report?** Recovery uses current source and traceable verification; historical claims are retained as history, not repeated as current facts.

### Authorization contract and implementation

`POST /api/routes/optimize` is protected by `Depends(require_manager)` in `backend/routers/routes.py`. `require_manager` permits active `manager` and `admin` users. It denies authenticated `user` and `driver` roles with HTTP 403. `get_current_active_user` and `get_current_user` validate the bearer token, resolve the current database user, and reject missing/invalid credentials with HTTP 401. Manager-only route planning writes use the same helper, including optimize, swap-trucks, create/update/delete route, start/complete, and driver assignment. Authenticated route/bin reads use `get_current_active_user`. Admin-only actions use `require_admin`, which admits only admin and denies other authenticated roles with 403. The Android driver identity uses a separate driver dependency; this phase does not change it.

The repair removes the nonessential emoji-bearing `print()` from both `require_manager` and `require_admin`. These shared authorization helpers now evaluate the role and raise their existing 403 response without writing to stdout. The HTTP authorization rules and allowed roles were not broadened. Removing the admin-helper print is part of the same shared authorization failure mode; it prevents that helper from producing the same output-encoding failure on admin-only endpoints.
